# @skillcdn/serve

## 0.4.0

### Patch Changes

- [`cd9e11c`](https://github.com/skillcdn/skillcdn/commit/cd9e11c78a468df5cb546b2936a86fea32e7a204) Thanks [@samo-lucid](https://github.com/samo-lucid)! - A deployment is searched across every public pack it serves. `@skillcdn/core` gains the result of such a search (`HubResult`, `HubItem`), its text for a model (`renderHubResult`, `renderHubInstructions`), the `search_packs` tool contract, the REST body and schema of `GET /api/v1/search` (`hubBody`, `restSearchSchema`, `hubResultOf`) and the manifest's `search.hub` field, which keeps a repository out of that search; `@skillcdn/serve` gains `createHubServer`, the MCP server of a deployment's root with the one tool, over a search a deployment provides; `@skillcdn/client` gains `search(query, limit)`.

- [`5f1c0fc`](https://github.com/skillcdn/skillcdn/commit/5f1c0fc271d72807f45944fc45cb32f810e67a9a) Thanks [@samo-lucid](https://github.com/samo-lucid)! - A mount of a private repository carries no provenance notice (ADR-0061): the notice follows a public repository nobody vouched for, and nothing else. `MountSummary` and the reader's `MountContext` take an optional `visibility`, read as `public` when absent, and the results read from the REST API take it from the repository's `visibility`. A directory served by the command is private and verified, as before, so nothing changes for it.

- [`0e2052c`](https://github.com/skillcdn/skillcdn/commit/0e2052c306625d0ebe75513c5e0ada3b4e23e5b5) Thanks [@samo-lucid](https://github.com/samo-lucid)! - A reader may be handed an index served in place of the one of the mount's own commit, while that one is being built or could not be: the `index` dependency's ready outcome takes a `substitute`, the commit the index was built from and the ref's `newest` commit with why it is not served. Every result then names the commit it was read from, the `Source` line of a tool result carries one clause more (`newest <commit> indexing`, `newest <commit> failed (<code>)`, or `being reindexed` for the same commit under newer reading rules), the connection instructions say so in one sentence, and the `mounts` route answers `newest` beside `commit` (`null` while the two are the same). The page the skills extension lists from such an index is kept as briefly as an empty one, so that the client asks again soon. A caller that hands over no substitute sees nothing new.

- [`95c13d0`](https://github.com/skillcdn/skillcdn/commit/95c13d0229f5102de02e201b43a498bb8a4e8f76) Thanks [@samo-lucid](https://github.com/samo-lucid)! - Over MCP, the outline of a file comes in pages that fill the response budget, up to the 1,000 headings an outline keeps, instead of twenty headings a page: a file of a thousand headings took fifty calls to outline. A limit named by the call still bounds the page, and the REST API pages by its limit as before. The reader's browse takes the most headings of an outline page as headings, beside limit.

- [`a9da901`](https://github.com/skillcdn/skillcdn/commit/a9da901f2a4a6b0f28a5e590e2214b8d700bb710) Thanks [@samo-lucid](https://github.com/samo-lucid)! - Breaking: packs of documents are served through their structure and their words (ADR-0063, phase A).
  
  - A search result names the sections of a document that matched: the heading path, the `offset` and `limit` that read the section with `read_repo_file`, and an excerpt, left out when it only repeats the document's summary. `FindItem` documents carry `sections`; the REST `find` body carries them as `sections` with a nullable `excerpt`.
  - `browse_repo` given a file path answers the file's outline: every heading with its level, text, offset and the length of its section, paged. `BrowseResult` carries `outline` (`FileOutline`) and the REST `browse` body carries `outline`.
  - The word rules read the scripts without word stems (Han, Hangul, Hiragana, Katakana) by pairs of characters, and a pack's `language` chooses the stemmer, English being the only one at present: `searchLexemes`, `queryLexemes` and `searchVectorOf` take a language, and `wordRulesOf` names the rules.
  - The search vector is built by the indexer and stored as it is: `IndexEntry.search` holds it in the text form of a PostgreSQL `tsvector` (`serializeSearchVector`, `parseSearchVector`, `serializeSearchQuery`), and `IndexEntry.searchBody` is gone. `IndexStore.search` takes the lexemes of a query instead of the query. The reading rules are version 11, so a deployment rebuilds the indexes it holds when they are next asked for.
  - New in `@skillcdn/core`: `outlineMarkdown`, `headingPaths`, `matchSections`, and the result types and REST schemas of sections and outlines.
  - The `skillcdn` command outlines a file with `browse <pack> <file>`, prints the sections a search matched, and `check` prints how many sections each document has.

## 0.3.0

### Minor Changes

- [`fd0f1ad`](https://github.com/skillcdn/skillcdn/commit/fd0f1adc7fc5490d198ca7e2f5e263434f4d0a8c) Thanks [@samo-lucid](https://github.com/samo-lucid)! - The address routes take the usage hooks the tools take: a read through the REST API is counted as a call of its route (`rest/mounts`, `rest/browse`, `rest/find`, `rest/skills`, `rest/files`), the first page of a skill as a load of the skill, the first page of a file as a read of it, and the client by the product token its user agent begins with (`clientAppOf`; `browser` for a browser), at the address the app resolves for it.

- [`76cc577`](https://github.com/skillcdn/skillcdn/commit/76cc5777c614a2965a10ad8ed598e884636fed4f) Thanks [@samo-lucid](https://github.com/samo-lucid)! - `@skillcdn/serve` is the edges of SkillCDN as a library (ADR-0057): `createMountServer` makes the MCP server of a mount, the four tools, the prompt and the skills extension over a reader, with what a deployment counts as optional hooks; `registerAddressRoutes` puts the five routes of the REST API that read an address on any Hono app; `createLocalApp`, `listenOn` and `serveOverStdio` serve mounts from a machine. The `skillcdn` command serves a directory with it: `skillcdn mcp <directory>` to the agent at the other end of standard input and output, and `skillcdn serve <directory>...` over HTTP on this machine, each directory at its `local/<owner>/<name>` address with the REST routes beside it, read again when its files change.
