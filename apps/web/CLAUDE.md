# apps/web: rules

Read the root [`CLAUDE.md`](../../CLAUDE.md) and this workspace's [`README.md`](README.md) first.

- **Keep the agreed direction.** The landing page leads with creative outcomes for beginners: the brand's symbol and wordmark (the files of `@skillcdn/brand`: the symbol in its own blue, the wordmark white on the dark ground and black on a light one, never another colour), one blue accent for controls, links and states with one warm point colour reserved for badges and the hero mark (`--color-point`, never a control), layered dark surfaces over the lit room of `tokens.css`, and a local concept clip. Keep setup details secondary to choosing a skill and starting a conversation. Larger changes of direction need a maintainer request.
- **Copy promises, it does not explain.** Landing copy is short and confident and leaves the how to the sections that show it; the promise is that someone who is not an expert gets a professional result from the AI they already use, said without saying so. Details belong in the FAQ, the connection guide and the docs, not in a hero line.
- **Tokens only.** No raw color, font stack or pixel size in a component's CSS: add or reuse a token in `src/styles/tokens.css`. The social-preview card is the one exception, because it is a picture.
- **Connection illustrations.** Client marks and illustrated client windows retain their own brand colors inside the dark, blue-accented site. Keep every caption and screen label in the language packs. These are illustrative guides, never live connection status; keep their steps aligned with the official references in `docs/specs/connect-guide.md`.
- **Fonts ship with the image.** The content security policy allows no foreign source, so a font is added as a package and imported in `entry-client.tsx`. Never link a font from a CDN. Only Hangul has a webfont, because only Hangul needs one: `styles/pretendard.css` is generated from the package and narrowed to the Hangul ranges, and Latin is drawn by the system fonts in `--font-sans`. Do not edit that file by hand. A font is a bundled dependency: its license must allow that (root `CLAUDE.md`, Dependencies), and its notice ships in `public/licenses/`, listed in `THIRD-PARTY-NOTICES.md`.
- **Every word goes through the language packs.** No user-visible string in a component. English is the source of truth; keep `ko.ts` in step in the same change, in natural Korean. The development-only pages are the exception. Language packs are the one place where committed text is not English.
- **Copy says what exists.** No prices or plans, no comparisons with other products, no promises about features that are not built. Naming an MCP client we work with is fine.
- **Same paths in every language.** The `lang` query parameter forces a language and makes it the visitor's preference, as the switcher does; without it the server answers in the language `Accept-Language` asks for, else the default, and says `Vary: Accept-Language`; the browser shows the visitor's preference, else the browser's language, and the URL stays clean (ADR-0009, ADR-0013, ADR-0015, ADR-0017, ADR-0021). Links inside the app go through `Link`, which never carries the parameter, so a copied link opens in each reader's language. Never read a cookie on the server to pick a language, and never redirect to put the parameter in the URL.
- **Pages that should be found are rendered on the server.** A new static page is added to `STATIC_PAGES` in `src/entry-server.tsx` and gets a head in `src/seo/head.ts`; the view of an address is rendered per request through `renderAddressPage`. Whatever renders on the server must render the same in the browser: no `window`, `Date.now()` or storage during render; read them in effects. A page that loads data asks for it through `useResource` with a key from `src/api/keys.ts`, which is how the server's answers reach it.
- **Nobody is signed in on the server.** A page is rendered as one document for everyone: the session is `unknown` during server rendering and on the browser's first render, and becomes known in an effect (`auth/session.tsx`). Never render something of a person's from anything but `useSession()`, and never branch on it in a way that makes the first browser render differ from the server's. What a signed-in person gets goes into the account pages as a section (`ACCOUNT_SECTIONS`), not into a new top-level route.
- **One way out to sign in.** Only `components/sign-in.tsx` links to the route that leaves for the git host (`loginPath`); the development states page is the one exception. Everything else that offers signing in opens the sign-in dialog (`useSignInDialog()`), which lies over the page and comes back to it; there is no sign-in page (ADR-0043). The button never stands without the sentence under it that says what continuing agrees to, which is why the component shows nothing until the deployment's links are known (ADR-0041).
- **What an app says about itself is its word.** On the consent page and in the list of connected apps, a client's name and page are shown as text, marked as its own, and never linked or fetched; the host its answer goes to is the fact shown beside them.
- **The documentation is the repository's own files** (ADR-0049). What a page says is changed in `docs/`, never here; a file is published by listing it in `docs/nav.json`, and `dev/docs.ts` reads it when the pages are built. A page is plain Markdown without front matter, and every relative link must lead to a file of the repository, with a fragment that names a heading of a published page: the build fails on anything else, and says where. A new section of `nav.json` needs its label in `docs.sections` of both language packs.
- **Repository content is hostile.** It reaches the DOM only through `components/markdown.tsx` or as text. Never `dangerouslySetInnerHTML`, never an `<iframe>`. A picture in repository Markdown is the one thing loaded from elsewhere (ADR-0030): an `https` URL as written, a path of the repository as the host's raw copy at the page's commit, always lazily and with `referrerPolicy="no-referrer"`; nothing else becomes an `<img>`.
- **No inline `style` attributes and no inline scripts**: the server sends a content security policy that forbids them.
- **The REST API is the only backend.** Responses are parsed with the schemas from `@skillcdn/core`. When the contract changes, `dev/fixtures.ts` changes with it; `dev/fixture-api.test.ts` fails until it does.
- **New runtime dependencies need a reason** in the commit message, like everywhere else. The main bundle is what every visitor downloads: what only the explorer needs is loaded with it (`lazy` in `src/app.tsx`).

## Gotchas

- The integrated server caches the built web manifest and templates at startup. Restart it after rebuilding `WEB_ROOT`; otherwise it can reference removed asset hashes. Vite development previews reload changes automatically.
- A video only plays on some phones when the server answers byte ranges, which the integrated server does; a static host or a cache in front has to as well. A clip's poster is its first frame on purpose: with any other frame, playback starts with a visible jump.
- Muted autoplay is not guaranteed: Samsung Internet can be set to refuse it, and saver modes refuse it. A refused clip becomes the same clip as an animated image, never a control laid over it; under reduced motion the page does not ask, and the poster stands. A remote desktop session turns Windows animations off, so a browser there reports reduced motion: check that before calling a clip broken.
- `boot.js` may hide a page while the visitor's language is applied, but must preserve the server's `html.lang`, which says what the server sent. The client decides whether to hydrate from the root's `data-lang`, which no script before it touches, and `html.lang`, which must agree; only `applyHead` changes `html.lang` after rendering.
- Two ways a soft light grows a hard edge, both of which look like a blur that is not strong enough and are not. A radial gradient reaches its farthest corner by default, so in a box that is rounded or not square it is still opaque where the rounding cuts it: say `closest-side` when the fill must end where the box does. And a mask image is tiled and clipped to its own box, so putting one on a blurred element cuts the blur off at the box edge — which, on a glow, is an arc across the middle of it. Darken with a veil over the light instead of masking the light.
- A box with no fill of its own cannot keep a fixed hairline. `--color-border` is a colour, so the line is only as visible as the difference between it and whatever is behind it, and over the lights that difference goes to nothing exactly where the page is brightest — measured, the rules between the questions ran 1.00:1, the very colour of the ground they were drawn on. A line that has to hold over a varying ground is white let through (`--color-border-lit`), which lightens whatever is behind it and reads the same everywhere. Keep the fixed colours for a line on a surface.
- A decorative light behind a section is `z-index: -1` inside it, which puts it behind that section and in front of every section painted before it — and `isolation: isolate` on the section is what keeps it there. Pin such a light with `position: fixed` and it is still painted with its own section, so it lands wherever the window is over everything above it: that is how a section light comes to lie on the hero's title instead of behind it. Without the isolation it falls through to the page's own negative layer, behind all of the page's words; keep the isolation only on a section that has a surface of its own for the light to sit over. And the first section is a case apart, because a `view()` timeline's `cover` range opens a whole window before its subject arrives: the first section is already part-way through its pass on the first screen, so a fade that starts dark leaves that screen unlit and only one that starts lit can light it.
- When a token suddenly does nothing, check that the comment above it closed. A stray `*/` in a declaration block makes the parser skip to the next `;`, which swallows the declaration under it; the token is then undefined, every `var()` on it is invalid at computed-value time, and the property falls back to its initial value with nothing said anywhere. It looks exactly like a value that has no effect.
- A custom property that holds `var()` references has them substituted where it is *written*, not where it is used: `--glass-surface` on `:root` carries the tint `:root` had, and an element that redefines `--glass-tint` on itself changes nothing about it. A variant of such a value is its own token, not an override of a part of it.
- A small round box with a number in it centres nothing. The line the text sits on is as tall as the page's line height, which is taller than a box the size of one line; a box that cannot hold its line puts the line at the top rather than the middle, and the number lands at the foot of the ring. Say `line-height: 1` so it fits, and remember that a fixed height splits a padding between both sides, so an optical lift there costs twice the padding it does in a box that grows with its text.
- Replacing a CSS module file wholesale can leave the Vite development server serving it as an empty module: the stylesheet itself is right (ask for it with `?direct`), but the default export has no class names and every `styles.x` comes out `undefined`, so elements render with no class at all and no error anywhere. Touching the file again invalidates it. Editing in place does not trigger it.
- A function in a language pack whose key begins with `use` reads to the linter as a React hook, and calling it inside a condition fails the check (`useHookAtTopLevel`). Name such a key for what it says, not `useSomething`.
- Biome rewrites `import "./x.css"` to `./x.js` (`useImportExtensions`). Style sheets that are imported for their side effect carry a `biome-ignore` for that; CSS modules are not affected.
- Adjacent expressions in JSX (`{host}{path}`) become separate text nodes with a comment between them in prerendered HTML. Write one template string when the text must be searchable as a whole.
- `--font-mono` has no Hangul: Pretendard is declared for the Hangul ranges only and sits in `--font-sans`. A Korean line set in the code face therefore splits in two, the Latin in a monospace and the Hangul in whatever the system offers. Only set code in `--font-mono` (an address, a path, a call, a digit); prose stays in `--font-sans`, however technical it looks.
- There is one theme and it is dark: `tokens.css` sets `color-scheme: dark` and every color is a single value. Nothing reads or writes `data-theme`. Large address fields, where used, carry their own light-surface text colors (`--color-*-invert`).
- Text reads from the left. What is centered says so in its own rule and is nearly always a header: the landing hero, a section title and its lead, the head of a page, the short pages (not found, bad address) and the header bar. Two things that are not headers: the pair of buttons under the authors section is centered, and the footer is not centered at all — its two halves sit at the two ends of the page.
- Headless Chrome will not make a window narrower than about 500 px; to check a phone width, load the page in a 390 px wide iframe.
- The render bundle imports `pages/mount.tsx` statically while the client loads it lazily; the build warns that the dynamic import is ineffective in that bundle. It is meant to be.
- The fixture server's sign-in is one fact for the whole process, not a cookie: following `/auth/gh/login` signs the fixture person in for every browser that talks to it until it restarts or someone signs out.
- The server hydrates the page of an address only when `#skillcdn-data` is there and `data-prerendered` names the route; otherwise the browser renders afresh. A mismatch between what the server and the browser render shows up as a hydration warning in the console: check `useResource` gets the same answers on both sides.
