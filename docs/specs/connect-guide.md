# Connection guide

The repository page helps a visitor connect its skills to an AI app without needing to understand MCP first. It offers ChatGPT, Claude, Cursor, VS Code, Claude Code, Codex CLI, Gemini CLI and a generic remote-MCP guide.

## Behavior

- Choose an app by its bundled icon and name, without category subtitles. The selector follows the ARIA tabs pattern, including arrow keys, Home and End; at phone widths it scrolls horizontally and keeps the selected app in view.
- Keep the complete mounted endpoint copyable, including origin, ref and path; never append `/mcp`. The manifest determines the example server name when present. Clients with an install link lead with an Add button and put the address and configuration under manual setup.
- Each client has three steps. Desktop screens show the selected preview alongside step buttons. Narrower screens show every step description and its preview in a vertical sequence, without accordion controls. All three previews are server-rendered; CSS controls which are visible, and each visible illustration runs its own loop. Preview titles use the app name, including ChatGPT and Claude.
- The selected step stays selected. Simple click scenes repeat every 3 seconds; a scene of two clicks, where the first opens a menu and the second chooses its entry, uses 4 seconds; typing and sending scenes use 6.4 seconds, as does a form that is filled in the order a person fills it: the address typed, a list opened and its entry taken, the form submitted, with one pointer that travels from control to control instead of one per control. There is no player, automatic step advancement, duplicate arrow/dot navigation or explanatory footer. A small Example label identifies the illustration.
- The loop runs only while visible. Hidden pages stop the clock; reduced-motion preferences show a complete static illustration. Switching step, app or language resets the animation. One clock synchronizes the pointer, typing and button states.
- Pointer targets align the cursor tip with the control center, without click rings. Toggle pointers target the switch itself, not its surrounding settings row. Text fields demonstrate typing without a pointer effect.
- English and Korean packs supply instructions and screen labels. Localized menus use their names without English parentheticals. Commands, file paths and native menu identifiers without a verified translation remain unchanged.
- Illustrated app controls do not operate the actual app, and their text remains selectable. Commands, editor configurations, form values and example messages also offer click-to-select-and-copy using the complete value, even during typing. Interaction reveals stable text until both focus and selection leave it, so looping animation cannot clear the selection. Shell launch commands and in-app slash commands are separate copy targets. Keyboard activation works, copy success is announced, and clipboard failure leaves the text selected for manual copying. Instructions remain present in server-rendered HTML; browser APIs are used only in effects and event handlers.
- Cursor, VS Code and Claude have prominent Add buttons opening their native install confirmation: Cursor's and VS Code's deep links, and Claude's add-connector dialog with `connectorName` and `connectorUrl` filled in, which Claude marks as coming from a link and asks the person to confirm. The button stands where the address would otherwise be, with what it does beside it, and the address waits under manual setup. ChatGPT's app-open link opens its Plugins page; none of these implies an undocumented installation API. Terminal clients show a copyable command. A generic client has no assumed universal JSON schema.
- A step says only what the app asks of the visitor. Claude and ChatGPT bring an added server into a chat on their own, so their last step is a message and nothing is switched on or mentioned per conversation. ChatGPT's steps are the same in its app and on the web: the Plugins page under Customize, Add, Create MCP app, a form with the name, a description the guide supplies (the repository's own, shortened, copyable from the illustration), the server URL, authentication chosen as none from a list whose default is OAuth, an acknowledgement to tick, and Create; Developer mode is not involved. The Add menu in the illustration shows only the entry to take, because the other entries change between releases.
- Finish with a copyable first message that names the server as the steps told the visitor to name it, so an agent with other servers and skills connected is asked about this one; the hint says to use whatever other name they gave it. The illustrated question names it too. No scene claims that a real connection has succeeded. Availability notes and official help explain missing menus without promising account access.
- All assets ship with the application, including icon licenses. No remote images, inline styles, third-party embeds or animation dependencies are needed. Website colors remain dark with one blue accent and the point colour on badges alone; client illustrations and marks use their native colors.

Recheck these sources when changing the steps, because client menus change independently of this project, and check the app itself where a help article lags behind it: Claude's connectors live on the Customize page (sidebar, or account menu → Settings → Connectors) with an Add menu whose entry is Add custom connector, and the dialog asks for a name and the MCP server URL and ends with Continue, while the help article still describes a + button and a per-chat toggle; and ChatGPT creates an MCP app from its Plugins page in the app and on the web alike, without Developer mode, which its developer documentation still describes.

When the service gains OAuth, the ChatGPT step changes: its authentication field then takes the app's "OAuth or no authentication" choice, which today fails to find an OAuth configuration on a public address, so the step says no authentication.
