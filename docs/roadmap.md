# Roadmap

What exists, what is being built, what comes next. Update this file in the same change that starts, finishes or drops an item. Detailed task tracking happens in GitHub issues; this file stays coarse.

## Done

- **Foundation.** Monorepo layout, pinned toolchain, lint, typecheck and test pipeline, CI, container image with role dispatch, license, contributor and agent documentation.
- **Milestone 1: serve a public repository end to end.** An MCP client connects to `/gh/<owner>/<repo>` for a public GitHub repository and can discover, load and read skills and documents: address and skill-repo parsers in `core`, the GitHub adapter, the first schema with full-text search, the `api` and `migrate` roles with lazy indexing, test-only repository fixtures, an end-to-end test with the MCP client SDK, and what the server needs to run behind a reverse proxy. Publishing and deployment are not part of this repository ([ADR-0008](adr/0008-repository-ends-at-an-image-that-builds.md)); the milestone is really over with the first hosted staging deployment.

- **Milestone 2: the web UI.** A person opens the service in a browser, understands what it does in their language, pastes an address and sees what an agent gets from it: REST API v1 ([specs/rest.md](specs/rest.md)); the landing page and the explorer in English and Korean, prerendered per language with metadata, structured data, social-preview images and `llms.txt` ([ADR-0009](adr/0009-web-ui-prerendered-per-language.md)), with the design decided with the maintainers (an approachable creative landing page, one blue accent, layered dark surfaces, and the brand's symbol); the server serves the build, renders the page of an address with its data so that it can be indexed, and generates `sitemap.xml` and `robots.txt` ([ADR-0011](adr/0011-address-pages-rendered-on-the-server.md)); the UI runs on its own for whoever designs it, from fixtures or against a running server; usage statistics per public repository and skill, and distinct clients counted without identifying one ([ADR-0010](adr/0010-distinct-clients-by-daily-keyed-hash.md)); search-console and analytics tags from configuration. Login and repository connection arrived with private repositories, in milestone 5.
- **Milestone 3: MCP in depth.** An agent that connects to an address knows what it got and uses it well, whatever the client, and a person who opens the page of a repository connects their agent from there. Skills travel through the MCP skills extension `io.modelcontextprotocol/skills` from the same index and publication policy as the four tools, which remain for discovery and for clients without the extension ([ADR-0024](adr/0024-skills-travel-through-the-mcp-skills-extension.md)); a skill on the wire is assembled from its sources ([ADR-0025](adr/0025-a-skill-on-the-wire-is-assembled-from-its-sources.md)); content is addressed by repository-root paths, with folder browsing, scoped search and skills loaded in pages ([ADR-0022](adr/0022-repository-paths-and-progressive-skill-loading.md), [ADR-0023](adr/0023-optional-introductions-and-explicit-publication.md)); a tool result is the one text written for the model ([ADR-0034](adr/0034-a-tool-result-is-the-text-written-for-the-model.md)); a file over the read limit is named with its source ([ADR-0033](adr/0033-a-file-over-the-read-limit-is-named-with-its-source.md)); a skill may include a shared page of the repository, which travels with it on every route ([ADR-0044](adr/0044-a-skill-may-include-a-page-of-a-shared-document-set.md)); the repository manifest gives names, descriptions, rules, document roots and translations ([ADR-0018](adr/0018-skillcdn-fields-in-skill-md-under-one-key.md)), the `check` role reports what the indexer reads ([ADR-0020](adr/0020-a-check-role-reads-a-working-tree-with-the-indexer.md)), and results carry a provenance notice until somebody vouches for the repository ([ADR-0019](adr/0019-the-operator-vouches-for-repositories-until-owners-can.md)). The page of a repository leads with the steps to connect it to the common clients ([guide contract](../apps/web/connect-guide.md)), the landing page and the explorer lead with what can be made, and a URL without a language is answered in the language asked for ([ADR-0021](adr/0021-a-url-without-a-language-is-served-in-the-language-asked-for.md)). The server survives hostile repository content and mixed-version deployments. An address serves only what is its repository's own ([ADR-0039](adr/0039-an-address-serves-only-what-is-the-repositorys-own.md)), and the server bounds its own work for requests from nobody: request and index size limits, bounded indexing per process, and a short memory of names that are nothing, shared between processes ([permissions](specs/permissions.md#what-is-served-to-whom)); limiting requests per client is the job of whatever sits in front. The extension passed the MCP Inspector's conformance checks, and the maintainers connected the real clients by hand, to a local server and to the hosted service. Nothing in this repository can test that, so it is done again after every change to what a client sees and whenever the protocol changes.
- **Milestone 4: ready for public operation.** A deployment that serves other people's repositories can say what it does with their content, honor their licenses, take content down, and show its visitors what it must; nothing in it is specific to one operator, and every switch has an off default that suits a private installation. The license a skill carries decides whether its body is served or only described with a link to its source, and the operator keeps verified, featured and blocked lists through a token-protected admin API, with a purge that removes what was indexed of a repository ([ADR-0026](adr/0026-serving-follows-the-license-and-the-operators-lists.md)). The legal surface is off until it is configured: links to terms and privacy pages and a contact for content reports, pages the operator can write into the deployment in every language it has ([ADR-0029](adr/0029-terms-and-privacy-pages-can-be-written-into-the-deployment.md)), analytics only after consent, and a checklist for public deployments in the deploy documentation. The license, notice and trademark files travel in the image, the web build carries the licenses of its bundled packages, and `pnpm check` refuses a production dependency under a license outside the allowlist. Distinct clients are counted under a key derived from a configured secret and the day ([ADR-0027](adr/0027-client-hashes-are-keyed-from-a-configured-secret-and-the-day.md)). The front page leads with a showcase the operator writes, with its media stored in the database and served by hash, and the explorer keeps its own featured list; a fresh deployment shows the reference repository on both ([ADR-0028](adr/0028-the-front-page-and-the-explorer-are-operator-content.md)). A repository declares its picture in its manifest, or the operator gives an address one ([ADR-0031](adr/0031-a-picture-for-a-repository-comes-from-its-manifest-or-the-operator.md)), and the page of an address unfurls with a card the server draws for it ([ADR-0032](adr/0032-social-previews-are-drawn-by-the-server-for-each-address.md)).
- **Packages on npm.** `@skillcdn/cli` (`skillcdn check`, so that an author sees what an agent would get without the image), `@skillcdn/indexer` and `@skillcdn/core` are published under the `@skillcdn` scope. The reading rules moved into a package of their own for it, with the types of an index in `core` ([ADR-0045](adr/0045-the-indexer-is-a-package-and-check-is-a-command.md)); each package has a changelog from changesets and all share one version ([ADR-0058](adr/0058-the-published-packages-share-one-version.md)), and the release workflow publishes through the registry's trusted publishing, with provenance and no stored secret ([ADR-0046](adr/0046-packages-are-published-to-npm-through-trusted-publishing.md)). The server stays unversioned: a deployment pins a commit. The pictures of the brand followed as `@skillcdn/brand`, a package of files under the trademark policy, for the reference console and whoever else may show them; the web UI serves them from it ([ADR-0048](adr/0048-the-brand-files-are-a-package-of-their-own-under-the-trademark-policy.md)).

- **Usage for operation.** The statistics count file reads by path and the deployment's totals over every repository without naming one, with distinct clients by the app they used, and the operator reads them through the admin API; what to rank or to recommend from them is for whoever consumes them. The pages tell analytics only what is public, as one funnel of page views and events, and the consent banner is a pane of the site's own glass ([ADR-0050](adr/0050-the-pages-tell-analytics-only-what-is-public-and-usage-is-counted-in-the-database.md)). The pages ask before analytics run only where the visitor's region asks, as a trusted proxy places the visitor, and run elsewhere with the footer offering to turn them off ([ADR-0051](adr/0051-analytics-ask-first-only-where-the-visitors-region-asks-and-run-elsewhere.md)).
- **Milestone 5: people and private repositories.** A person signs in with their git host and uses a private repository from the pages and from their AI app, with the host deciding who sees what, and an account has a page of its own; the contract is [specs/permissions.md](specs/permissions.md). Signing in through a GitHub App, with the person's token encrypted at rest and the host's answer cached briefly and failing closed ([ADR-0035](adr/0035-people-sign-in-through-the-git-hosts-app.md)); the deployment as the OAuth 2.1 authorization server of its addresses, for clients that sign in over MCP ([ADR-0036](adr/0036-the-deployment-is-the-authorization-server-of-its-addresses.md)); the sign-in dialog, the account menu and pages and the consent page ([ADR-0041](adr/0041-a-sign-in-begins-on-a-page-of-the-deployments-own.md), [ADR-0042](adr/0042-every-sign-in-passes-the-git-hosts-account-picker.md), [ADR-0043](adr/0043-a-sign-in-begins-in-a-dialog-over-the-page.md)); the page of an account ([ADR-0037](adr/0037-an-account-has-a-page-made-from-what-the-git-host-shows-everyone.md)); the git host's events, which only ever end what is remembered ([ADR-0038](adr/0038-the-git-hosts-events-end-what-is-remembered.md)); and repository tokens for agents with nobody to sign in, taken by MCP and REST alike, with or without an end ([ADR-0040](adr/0040-a-token-for-an-agent-reads-one-repository-as-its-maker.md), [ADR-0052](adr/0052-the-rest-api-takes-the-tokens-the-mcp-endpoint-takes.md), [ADR-0060](adr/0060-a-repository-token-may-have-no-end.md)). Tried by hand against a real GitHub App and the clients of the connection guide; what a client shows when it signs in can only be seen in the client, so this is done again after every change to what a client sees.
- **The command serves what MCP serves.** An agent with a shell and no MCP connection reads a pack through the `skillcdn` command, from a deployment or from a directory on its own machine, and a directory is served as MCP and REST from that machine without a server or a database, offline or in a network that reaches no git host; what the command answers is what a deployment would answer ([ADR-0053](adr/0053-an-address-may-name-a-pack-served-from-a-machine.md)). The word rules of search in `core`, held against the server by an integration test; the REST shapes and their results both ways; `@skillcdn/reader`, the reads over an index-store port ([ADR-0054](adr/0054-the-reads-are-a-package-over-an-index-store-port.md)); a directory read into an index in memory and the command's reads of it ([ADR-0055](adr/0055-the-command-reads-a-pack-as-a-deployment-serves-it.md)); `@skillcdn/client` ([ADR-0056](adr/0056-the-rest-api-has-a-client-and-the-command-reads-a-deployment-through-it.md)); `@skillcdn/serve`, with `skillcdn mcp` over stdio and `skillcdn serve` over HTTP ([ADR-0057](adr/0057-a-directory-is-served-by-the-command-over-stdio-and-http.md)); REST reads counted as tool calls are; and a command that connects to a deployment with a code a person approves on its pages, keeping the repository token it is handed and binding a checkout to a directory ([ADR-0059](adr/0059-the-command-connects-with-a-code-a-person-approves.md)).

## Next

Phases: A, structure and words, with no model anywhere; B, meaning with reranking, the worker, the admin reads, the model profiles measured on the evaluation set, and the inference server in the compose bundle; C, the explorer's search and search across repositories. **Started: phase A is built.** A search result names the sections that matched with the offset and limit that read each, `browse_repo` given a file answers its outline, the word rules match the scripts without word stems by pairs of characters and read a pack with the stemmer its `language` names (English, the one stemmer so far), the search vector is built once by the indexer and stored as it is by every index, and the retrieval evaluation set lives in the fixtures with its lexical baseline ([specs/tools.md](specs/tools.md#sections-in-a-search-result), [specs/skill-repo.md](specs/skill-repo.md#document-packs), [specs/rest.md](specs/rest.md), [the evaluation set](../apps/server/fixtures/retrieval/README.md)); the two skills of the reference pack, making documents into a pack and working a large one, are written in `skillcdn/skills`. Phase B has begun: the `Embedder` and `Reranker` ports are in `core`, and the server has the one adapter of each, speaking the common embeddings and reranking APIs, with the configuration of the servers, their timeouts, how many calls one process has in flight at once and how sections are packed into a call ([deploy](../deploy/README.md)); and the `worker` role runs the jobs of the queue, on pg-boss in the database: a repository indexed on request, the sections of every indexed commit embedded body by body in slices that take turns, and an hourly sweep that backfills what is served after a change of model and drops the old model's vectors once it is done ([deploy](../deploy/README.md#the-worker)); and a search fuses the sections nearest in meaning with the words' results by reciprocal rank fusion, reranks the first of them where a reranking model is configured, answers by words alone when either does not answer in time, and says in one line how it ranked ([specs/tools.md](specs/tools.md#words-and-meaning)); and what is embedded is bounded: by the scope a deployment configures, none, public or all, by the `Entitlements` port, which gained the `embed` action with bounds on the bytes per repository and per account and day, metered through the `UsageSink` with the tokens the model read, and by a manifest that keeps its documents to the words ([deploy](../deploy/README.md#the-worker), [format](specs/skill-repo.md#the-repository-manifest-skillcdnmd)); and the admin API reads how the queues stand and what failed, where the embedding went and what it took per day, designates an address for indexing now, and imports vectors computed elsewhere against the stored bodies and the model in use ([deploy](../deploy/README.md#the-admin-api)); and the `skillcdn` command, given the variables a deployment takes, embeds a directory's sections with a server on the person's machine and keeps the vectors in the cache directory by the hash of each file, so that a directory is embedded once and a changed file again, with `find`, `mcp` and `serve` ranking by words and meaning ([the command](../packages/cli/README.md#searching-by-meaning)), the adapters having moved into `@skillcdn/inference` for it ([ADR-0066](adr/0066-the-inference-adapters-are-a-package-of-their-own.md)). And the pages: the page of a repository says how it is searched, words or words and meaning, and how far the embedding of its documents has come, with the connection instructions saying the same in one line so that an agent asks in the pack's words or in its own; whoever administers the repository at the git host has it indexed now from the page, a repository that is not public as well ([REST](specs/rest.md#get-apiv1meindexaddress-and-post-apiv1meindexaddress)); and the explorer lists the sections a search matched under a document and opens the file at one.
