# ADR-0065: Meaning search runs on open-weight models served beside the image, for embedding and for reranking

- Status: Accepted
- Date: 2026-10-20
- Amends: [ADR-0064](0064-meaning-search-runs-on-pgvector-and-pg-boss-behind-an-embedder-port.md) (point 1, which left the model to a hosted provider or a self-hosted server alike, and the reranker to a later phase).

## Context

[ADR-0064](0064-meaning-search-runs-on-pgvector-and-pg-boss-behind-an-embedder-port.md) put the model behind one port and one adapter and left the choice of model to configuration, hosted or self-hosted. The maintainer decided against hosted models from the start: a pack's text is the organization's, and a private pack's text must not leave the deployment to be embedded; a self-hosted deployment and the hosted service should give the same answers to the same pack; and the choice of model should be made once, on measured quality, not per provider. Reranking was planned for a later phase; it is to come with meaning search, since the first ten results of a fused search are where the quality is decided.

The packs are written in English and in Korean first, and in any other language next. Open-weight models of the last year cover a hundred languages in one model, take long inputs, and are served by several inference servers that speak the same two HTTP shapes, one for embeddings and one for reranking. Their licenses allow a deployment to run them for anyone.

## Decision

1. **Open weights only, under a permissive license.** A deployment runs the embedding and the reranking model itself, on an inference server beside the image, or a person runs one on their machine for the command. No text of a pack is sent to a model anyone else operates. The adapters of ADR-0064 stay as they are: the common embeddings shape (`POST /v1/embeddings`) and the common reranking shape (`POST /v1/rerank` or `/rerank`: a query, the candidate texts and how many to return, answered with each text's index and score; the field names differ between servers and the one adapter reads both spellings).
2. **Embedding and reranking both, in the same phase.** A `Reranker` port joins the `Embedder` port in `core`: rerank a query against candidate texts into scores. The fused results of words and meaning are reranked before the page is cut, with a short timeout, and without the reranker when it does not answer. The reranker may be absent from a deployment; the embedder may not, where meaning search is on.
3. **The models are chosen on four criteria**, in this order: quality in English and in Korean, measured on the evaluation set of [ADR-0063](0063-packs-of-documents-are-served-to-agents-through-structure-words-and-meaning.md); quality across the other languages a pack may be written in; a license that allows a deployment to run the model for anyone, Apache-2.0 or MIT; and an input long enough for a section and an output of 1024 dimensions, so that every candidate fills the same column and a change of model changes no schema.
4. **The first choice is the Qwen3 embedding and reranking family**, Apache-2.0, trained for more than a hundred languages, with inputs of thirty thousand tokens and user-chosen output dimensions, fixed here at 1024. Two profiles: the *base* profile runs the 0.6B embedding model and the 0.6B reranker, and works on CPUs; the *quality* profile runs the 4B embedding model and the 4B reranker, and wants one GPU. The embedding model expects a one-line task instruction in front of a query and none in front of a document; the adapter adds it from configuration. Where a pack is Korean above all and the evaluation set shows a gap, KURE-v1, a Korean fine-tune of BGE-M3 under MIT with the same 1024 dimensions, is the alternative embedder, and bge-reranker-v2-m3 under Apache-2.0 the lightweight alternative reranker. Which profile the hosted service runs is an operating choice and is not written here.
5. **A change of model is configuration and a backfill**, never a schema change: vectors are keyed by model ([ADR-0064](0064-meaning-search-runs-on-pgvector-and-pg-boss-behind-an-embedder-port.md)), the worker re-embeds under the new key, and the old vectors are dropped when nothing searches by them. The evaluation set is run before and after.
6. **The deployment contract gains an inference service where meaning search is on.** The image stays one image; the compose bundle of the roadmap carries the inference server with the two models, and the deployment documentation says how an installation without internet mirrors the weights. The models are not inside the image: their size would multiply it, and an installation that searches by words alone should not carry them.

## Consequences

- A deployment that leaves meaning search off changes nothing. One that turns it on runs one more container and no account with anyone.
- Hosted and self-hosted answer the same pack the same way when they run the same profile.
- The quality of Korean retrieval is measured, not assumed: the first model is the strongest general multilingual choice under a permissive license, and the Korean-specialized alternative is a configuration away if the numbers say so.
- CPU-only installations embed slowly: a pack of thousands of pages takes the worker hours on the base profile, which is why embedding runs after a commit is indexed and never while a request waits.
- Rejected: hosted embedding APIs, even for public packs (two code paths for one answer, and a dependency on another's terms); shipping the weights inside the image (a gigabyte or more for every installation, most of which search by words); a multi-vector model for Korean (a different storage profile, against the one column of pgvector); models under non-commercial licenses, however they score.
