# ADR-0084: An encrypted original stays encrypted, and nothing that opens it is in the pack or the image

- Status: Accepted
- Date: 2026-11-11
- Builds on [ADR-0076](0076-originals-travel-in-the-pack-and-the-repositorys-visibility-decides-who-reads-them.md), [ADR-0077](0077-the-bytes-of-a-file-that-is-not-text-are-sent-from-where-they-are.md) and [ADR-0071](0071-a-deployment-serves-packs-from-a-directory-of-its-own.md).

## Context

The originals a document pack was made from travel in it, in `sources/` ([ADR-0076](0076-originals-travel-in-the-pack-and-the-repositorys-visibility-decides-who-reads-them.md)). Some originals arrive encrypted: a PDF that opens with a password. Three things were undecided: in what state such a file travels, where the password is kept, and what a reader is told.

What the password is needed for decides where it may be. The conversion needs it once, on the machine that converts. A person who opens the original to check a figure needs it, and has it already, by whatever the organization does with its passwords. SkillCDN does not need it: the server indexes text and sends the bytes of an original as they are, from the git host or from the disk ([ADR-0077](0077-the-bytes-of-a-file-that-is-not-text-are-sent-from-where-they-are.md)), and opens nothing.

And the conversion is the step that takes the protection off. The text of an encrypted original is in the chapters made from it, in the clear, for whoever may read the pack. The password guards the file; the pack's readers are what guards the content.

## Decision

1. **An encrypted original travels as it was received, encrypted.** A copy with the protection taken off is not committed. The manifest of its document set says so: `originals`, a mapping with `encrypted: true` and, optionally, `key-name`, the name the organization knows the key by, one word. The nearest manifest that says anything of originals decides for a file.
2. **The pack never holds what opens an original**: not in a front-matter, not in a manifest, not in a note or in what the conversion wrote down. Everything of a pack is served as text to whoever reads it, into the context of every agent, and stays in the history of its repository. The name of the key is all a pack carries of the key. A front-matter key written to hold a password (`password`, `passphrase`, `pdf-password`, one mapping down as well) is the diagnostic `password_in_front_matter`, which names the key and never repeats the value; a password that was pushed is changed, since the history keeps it.
3. **Neither the image nor a deployment holds it.** No variable takes a password and nothing reads one. Building it into an image was considered and rejected: an image is a file that is copied to registries, to the media an installation without a network is delivered on and to backups; whoever can pull or load it reads every layer of it, a secret removed in a later layer included; changing the password means building and delivering the image again; and the published image is public, so only an image built for one site could carry it, which would then have to be kept as closely as the password itself and travels much further.
4. **SkillCDN does not open originals.** Decrypting on the way out, with the password as a secret of the running deployment, was considered and is not built: it would make reaching the deployment the same as holding the key, which for the packs of a deployment's own directory is everyone on its network ([ADR-0071](0071-a-deployment-serves-packs-from-a-directory-of-its-own.md)); it would put a PDF implementation in the image to parse repository content, which is untrusted, with a secret in hand; and the text is in the chapters already. Should a deployment ever have to open originals, that is a decision of its own, and the key would arrive as a file mounted when the container runs, under the name the pack already gives it, never in an image and never in a pack.
5. **The password stays where the organization keeps its secrets.** The conversion is given it for its run, through the environment of the tools that convert, never typed into a conversation and never written down by it; the people who may open the original hold it as they did before there was a pack. How the conversion takes it is the method's, in the reference pack.
6. **Who reads the pack is who may read the original opened.** A set converted from protected originals goes in a repository whose readers are the people cleared for those originals, a private one ([ADR-0076](0076-originals-travel-in-the-pack-and-the-repositorys-visibility-decides-who-reads-them.md)), or in the directory of a deployment whose network is theirs; a repository is the unit a git host gives access by, so originals for different readers are different packs.
7. **`check` holds the files against the manifest.** In a working tree, where the bytes are at hand, a PDF under a manifest that says its originals are encrypted is looked at where a PDF says that it is, its trailers, and nothing of it is parsed further: one that is not encrypted is `original_not_encrypted` and fails the check; one that is encrypted where no manifest says so is a note. A deployment fetches no original, so it takes the manifest's word.
8. **A result says that an original is encrypted**, where it names it: `Original: <path> (<url>; encrypted, key <name>)`, and `encrypted` and `keyName` over REST, so that an agent does not fetch a file it cannot read and a person knows which key to ask for. The reading rules move to version 17.

## Consequences

- A pack made from encrypted originals is the chapters, the pictures, and the files as they came; taking the pack somewhere takes no key along.
- The format gains one field of the manifest, the index one fact per manifest, and `check` one look at the two ends of each PDF; the server gains nothing that could leak.
- An agent that needs what is only in the original, a figure the conversion did not describe, asks a person: the conversion's descriptions of pictures are what agents read ([ADR-0063](0063-packs-of-documents-are-served-to-agents-through-structure-words-and-meaning.md)).
- The check looks at PDFs alone. Another format that can be encrypted is not looked into, and says nothing either way.
- The specification pack of the fixtures carries such an original: a PDF in the shape of an encrypted one whose password nobody ever had.
- Rejected, besides the image and decrypting on the way out: the password in a private repository (private is who may read today; the history and every clone keep it, and an agent that reads the pack reads it); an encrypted archive of the whole pack (nothing could be indexed, which is the pack's purpose); a decrypted copy beside the encrypted one (the copy is the leak); leaving the original out by rule (the reference to "page 12 of the original" would point at nothing a reader of the pack can reach, which is what ADR-0076 set out to end; a pack may still name an original by its title where the file may not travel).
