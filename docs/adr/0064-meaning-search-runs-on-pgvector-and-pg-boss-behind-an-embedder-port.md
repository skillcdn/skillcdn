# ADR-0064: Meaning search runs on pgvector and pg-boss behind an embedder port, bounded per deployment and per repository

- Status: Accepted
- Date: 2026-10-20
- Builds on [ADR-0004](0004-postgresql-only-state.md), [ADR-0007](0007-snapshot-rows-coordinate-indexing.md), [ADR-0054](0054-the-reads-are-a-package-over-an-index-store-port.md) and [ADR-0063](0063-packs-of-documents-are-served-to-agents-through-structure-words-and-meaning.md).

## Context

[ADR-0063](0063-packs-of-documents-are-served-to-agents-through-structure-words-and-meaning.md) adds a search by meaning as an optional layer. It needs a model that turns text into vectors, a place to keep the vectors, work done after a commit is indexed rather than while a request waits, and bounds, since embedding is paid for per token and sends the text to whoever runs the model. [ADR-0004](0004-postgresql-only-state.md) chose PostgreSQL as the only stateful dependency, with pgvector for vectors and pg-boss for jobs when they came; neither is in use yet. File bodies are kept under their git blob hash, so that what did not change is never fetched twice ([ADR-0007](0007-snapshot-rows-coordinate-indexing.md)); the same holds for what is computed from them. The command serves a directory with no PostgreSQL ([ADR-0053](0053-an-address-may-name-a-pack-served-from-a-machine.md)). The hosted service cannot carry model costs for every repository anyone mounts; a self-hosted deployment or a person's machine can carry what it chooses. Where a standard implementation exists, this repository takes it and builds only what gives it an advantage of its own.

## Decision

1. **An `Embedder` port in `core`**: embed a list of texts, as documents or as a query, into vectors; say the model's id, its dimensions and how much text it takes at once. One adapter, in its own package or in `apps/server` until a second consumer appears: the embeddings HTTP API of the common shape, `POST /v1/embeddings` with the request and the response that hosted providers and self-hosted model servers share, configured by a URL, a model name, a key read from a variable or a file, and optionally the dimensions. No provider's SDK. Changing the model is changing the configuration.
2. **Vectors live in PostgreSQL under pgvector**, keyed by the content they were computed from: the blob hash, the model and its dimensions, the version of the sectioning rules, and the section's index, with the section's heading path, character offset and length beside the vector. A section embedded once serves every commit, ref and fork that holds the same bytes; a changed model is a new key, and the old vectors are dropped when nothing is searched by them. The search is an exact nearest-neighbor scan over the sections of one mount's entries, with no approximate index until a search across repositories asks for one. The extension is created by a guarded migration: where `vector` is not installed, the tables are not created, meaning search stays off and everything else runs, so that the deployment contract remains PostgreSQL alone; the development compose file uses an image that ships the extension.
3. **Jobs run on pg-boss**, in its own schema, which the `migrate` role creates and the `api` and `worker` roles use without migrating. The `worker` role of the roadmap runs them; `api` enqueues. Three kinds: embed the sections of a snapshot once it is ready; re-embed a repository for a new model; index and embed a repository on request, which is the designated indexing an operator or an owner asks for. Priorities in that order reversed, designated first and backfill last; the queue is drained by account in turn, so that one large repository does not starve the others; every job is idempotent under its key, repository, commit and model, and retries with backoff.
4. **What is embedded is bounded by configuration and by the `Entitlements` port.** `EMBEDDINGS_SCOPE` is `none`, `public` or `all`, and `none` by default: a deployment that configures no model and no scope searches by words alone, as today. A repository is embedded when a search first asks for it, at the lowest priority, or when it is designated; a pack may opt a document set out in its manifest. `Entitlements` gains an `embed` action with limits on bytes per repository and per account and day; the `UsageSink` carries an embedding event with the tokens and the model, so that whoever operates a deployment can meter it; none of the numbers live in this repository.
5. **The admin API reads the jobs and the embeddings**: queue depth and age by kind and priority, failures, vectors and bytes per repository, tokens embedded per day; it designates an address for indexing now; and it imports embeddings computed elsewhere, for an operator who runs a model of their own in bulk, checked against the stored blob hashes and the configured model.
6. **The command serves meaning for a directory when a local model is configured**, by the same adapter at a local URL, and keeps the vectors in a cache in the person's configuration directory, keyed like the deployment's rows, so that a directory of thousands of pages is embedded once and re-embedded only where its files changed. Without a model the command answers structure and words, as ADR-0053 requires it to answer what a deployment answers.
7. **Privacy and removal.** Embedding sends the text of a repository to whoever serves the model; the deployment documentation says so, and a private repository is embedded only under `all`. Vectors are content-addressed like blobs and reached only through an index entry the caller may see; purging a repository removes them with its entries, and the janitor deletes what no entry names.

## Consequences

- One port, one adapter and two dependencies already decided in ADR-0004: nothing new to operate for a deployment that leaves meaning search off.
- A search by meaning costs nothing at request time but one small call for the query, and nothing at all where no model is configured.
- The specifications gain the scope and the bounds in the deployment contract, the jobs and the imports in the admin API, and the sections in the tool results; `check` reports the sections of a document as it reports its files.
- Serving a directory from a deployment's own filesystem, for an installation with no git host at all, is wanted and is not decided here: it changes what a `local` address means to a deployment ([ADR-0053](0053-an-address-may-name-a-pack-served-from-a-machine.md)) and gets an ADR of its own when it is built.
- Rejected: vectors as bytes ranked in the process (the extension does this, and a cache per index with a byte budget is code of our own for no gain); a jobs table of our own over the snapshot lease pattern (the library has retries, schedules and fairness primitives already); a vector database (a second stateful dependency, against ADR-0004); embedding at request time (a model call per search, and no search when the model is away); vectors committed to the repository (tens of megabytes bound to one model, in a place meant for content); an approximate index from the start (a mount has thousands of sections at most, and exact search over them is milliseconds).
