# ADR-0063: Packs of documents are served to agents through structure, words and meaning

- Status: Accepted
- Date: 2026-10-20
- Builds on [ADR-0022](0022-repository-paths-and-progressive-skill-loading.md), [ADR-0053](0053-an-address-may-name-a-pack-served-from-a-machine.md) and [ADR-0054](0054-the-reads-are-a-package-over-an-index-store-port.md). The mechanics are [ADR-0064](0064-meaning-search-runs-on-pgvector-and-pg-boss-behind-an-embedder-port.md).

## Context

Two things are wanted of a pack beyond its skills. An agent should explore the documents of a repository freely, a team's development documentation for one, and an agent should work over a large body of documents, thousands of pages, finding and reading what a task needs while a skill of the pack says how. Search today matches words as written, at the level of a file, and answers a title and a summary; a passage inside a long document is found by reading the file. A repository written in a language whose words carry particles or inflections is found only by its exact words.

The usual answer is a retrieval pipeline that embeds fragments of text, finds the nearest to a question and hands them to a model that writes the answer. It does not fit here. SkillCDN indexes and serves and never answers; the agent that connects is the model, and it reads, browses and searches with the tools it has. Agents that work over code have shown that a well-made harness over plain search outperforms a vector index for most of what they do, and that an index goes stale as fast as the content moves; agents that work over long documents do best when the document's own structure is in front of them and they reason their way down it, since what is similar to a question is not always what answers it. Where embeddings earn their place is the question that uses other words than the document, the question in another language than the document, and the mention somewhere in thousands of pages that no table of contents names.

Git stays the source of truth: the repository holds the content, the deployment indexes and serves it, and a directory on a machine is served the same way by the command, which must answer as a deployment answers ([ADR-0053](0053-an-address-may-name-a-pack-served-from-a-machine.md)). Repository content is data and nothing in it runs. The hosted service cannot afford a model call per document or per request; a local installation can.

## Decision

1. **Retrieval only.** SkillCDN finds and serves; the agent reads and writes. No model inside SkillCDN answers a question, summarizes a document or rewrites a result.
2. **Three layers, in this order of importance.** *Structure*: what the pack says about itself, with no model. *Words*: the lexical search of today, always present, deterministic, the same in a deployment and in the command. *Meaning*: a search by embeddings, optional, present where the operator of a deployment or the person running the command has configured a model, and never the only way anything is found.
3. **Structure is the pack's own and lives in the repository.** The README of a document set is its map, one line per document, as the introductions of [ADR-0023](0023-optional-introductions-and-explicit-publication.md) already are; the headings of a Markdown file are its outline, which `browse_repo` answers for a file path, each heading with its character offset and size, so that a long document is walked by its structure. A search result names the sections that matched inside a file, with the heading path, the character offset and length and a short excerpt, so that one `read_repo_file` call reads the passage. Content a mount describes without serving gets no excerpt.
4. **Words match across languages as the pack's `language` says.** The word rules of `core` gain character bigrams for scripts without word stems, Korean, Japanese and Chinese among them, so that an inflected word is found by its stem; a pack's `language` selects the stemmer on both sides, the deployment's built-in configuration and, in the command, an implementation of the same stemming algorithms, held equal by the parity test. No morphological analyzer becomes a dependency.
5. **Meaning is fused with words, never substituted for them.** The sections a model finds nearest and the files the words find are joined by reciprocal rank fusion, with the skill boost and the path order of today; a query is embedded with a short timeout and, when the model does not answer, the words answer alone. What a section is embedded as is its heading path and its text, so that the fragment carries its context without a model writing any.
6. **Ingestion is the agent's, outside the server.** Documents become a pack by a skill of the reference pack: converted to Markdown by the tools the agent has, laid out one file per document or chapter, each with a title and a description, every document set with its map, the manifest with its document roots and `language`, committed to a repository the person owns. SkillCDN never receives a file: it indexes what the git host, or the directory, holds.
7. **Images are understood by the agent, at ingestion, and indexed as text.** Alternative text and captions are part of a document's body and are searched already; a description of a figure, or the text of a scanned page, is written by the agent's own vision model into the repository, as a caption or a page beside the image. The server embeds no image and runs no vision model; a local installation uses what models it likes, through the agent.
8. **How an agent works a large pack is a skill**, in the reference pack: read the map, search, read sections, keep what was learned as notes committed to the repository through the agent's own access to git. The pack's own rules travel with every skill as they do today.
9. **A pack that is mostly documents is a document pack.** The word names a use of the pack, not a kind: the format, the address and the tools are the same.
10. **A retrieval evaluation set lives in the fixtures**: questions with the sections that answer them, in English and in Korean, so that a model or a rule is changed against a number.

## Consequences

- The agent's two purposes are served in steps: structure and words alone make a pack of thousands of pages workable with no model anywhere; meaning adds the questions words miss, where someone pays for a model.
- The command answers a directory the same way, structure and words always, meaning when a local model is configured ([ADR-0064](0064-meaning-search-runs-on-pgvector-and-pg-boss-behind-an-embedder-port.md)).
- A document pack has a layout rule the format spells out, a file per document or chapter rather than per page, since the limits of a deployment bound files and bytes per commit.
- The specifications of the tools, the format and the REST API change when each layer is built, and the guides with them; the roadmap carries the phases.
- Rejected: a tool that answers a question from retrieved passages (generation is the agent's, and a second model inside the server would answer with content the agent cannot see); retrieval by fragments alone, without the pack's structure (fragments lose their place, and a page of them tells an agent nothing about what else there is); image embeddings in the server (heavy, and the agent at ingestion sees the image better than an index does); a morphological analyzer for Korean (a native dependency for one language, where bigrams and a multilingual model cover the inflected scripts together).
