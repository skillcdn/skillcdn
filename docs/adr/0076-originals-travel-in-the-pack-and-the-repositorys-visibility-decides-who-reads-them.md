# ADR-0076: Originals travel in the pack, and the repository's visibility decides who reads them

- Status: Accepted
- Date: 2026-10-30
- Builds on [ADR-0063](0063-packs-of-documents-are-served-to-agents-through-structure-words-and-meaning.md) (points 6 and 7: conversion is the agent's, and images become text) and on [ADR-0039](0039-an-address-serves-only-what-is-the-repositorys-own.md). How the bytes of such a file reach a reader is [ADR-0077](0077-the-bytes-of-a-file-that-is-not-text-are-sent-from-where-they-are.md). The format is in [specs/skill-repo.md](../specs/skill-repo.md#document-packs).

## Context

A document pack is made by an agent from files a person has, PDFs, office documents, scans, converted to Markdown with the tools the agent has (ADR-0063). The first conversions on real specifications showed what the converted text alone cannot carry: a figure the agent described in a sentence, a table it flattened, a scanned appendix it transcribed, a page it summarized. The conversion notes said "page 12 of the original", and the original was nowhere the agent, or the person reading the answer, could reach: the reference skill left originals out of the pack and told the agent to strip personal data and secrets on the way, so that the pack could be served to anyone who held its address.

That was the wrong place to decide who may read what. A repository already has a visibility, and the deployment serves a private repository only to the people the git host lets see it (ADR-0035, [specs/permissions.md](../specs/permissions.md)). A pack made from private material belongs in a private repository, whole; a pack made for everyone has nothing to strip. The format also had to say where originals go and how a document points at one, which until now only the skill in the reference pack said, in its own words.

## Decision

1. **The originals a document was made from travel in the pack.** They sit in `sources/` inside the document set they belong to, beside the Markdown made from them, and are committed, or copied into the directory, like any other file of the pack. They are listed and never searched; an agent reaches one through its link, which [ADR-0077](0077-the-bytes-of-a-file-that-is-not-text-are-sent-from-where-they-are.md) makes real for every kind of pack. A file GitHub does not take as it is goes through Git LFS, which the link follows.
2. **A document names its originals in `source`.** The front-matter field holds the path of the original, written as a link destination is, relative to the document or from the repository root, or a list of them; any other text, a title or a URL, stays text. A result names the original with the document: `browse_repo` in the header of the outline, `read_repo_file` on the first page, each with where the bytes are. A page of an original is said in words ("page 12 of the original"), since the hosts that serve originals send them as downloads, where an anchor into a page does nothing.
3. **Conversion keeps what the original says.** Nothing is left out for being personal or secret: a pack is faithful to its sources, and who reads it is decided by the visibility of the repository that holds it. Material that is not for everyone goes in a private repository, with its originals. The format and the skill say so as an intent, not as an instruction to include anything.
4. **What looks secret or personal is pointed out, and the person decides.** The agent that converts lists what it found, with the visibility of the repository, and the person chooses to keep it, to leave it out of the converted text, or to make the repository private; leaving it out of the text leaves it in the original, which the pack still carries, so the choice is shown whole.
5. **The pictures of a document are part of it.** A picture is linked from the document with the words an agent reads it by, its alternative text or a caption, and is kept beside the document, in `images/` by convention; the agent at conversion writes those words (ADR-0063, point 7). `check` and the index say when a picture has no words, when a link, a picture or an original names no file of the repository, and when a skill, which works from text, refers to a file that is not text. A document's link to its original or its picture is what the format asks for, and is not reported.
6. **The format is defined in this repository, the method in the reference pack.** The specification and the guides of this repository say everything a pack has to be, skill packs and document packs alike; `skillcdn/skills` holds the skills that make one and work one, is linked as the official example, and defines nothing.

## Consequences

- An agent that works a document pack reaches the original behind every chapter: to check a figure, a table or a transcription, or to hand the file to a person. The conversion notes point somewhere.
- The format's rule on what a pack may hold is the visibility rule: nothing in a public repository that is not for everyone. The rule about real people's identity and likeness leaves the format, since it concerned the reference pack's own content; that pack keeps it in its own rules.
- A pack with its originals is larger, and the index must not pay for the files it never reads: that is ADR-0077's.
- The guides split: writing a pack in general, writing skills, writing documents, so that each kind of author reads what applies, with one page for what both share.
- Rejected: stripping personal data at conversion (the original would have carried it anyway, and the repository's visibility is the control that exists); originals kept outside the pack (the links pointed nowhere); the server converting or searching originals (ADR-0063: ingestion is the agent's); a `source` that is a URL to a document system of the person's (allowed as text, since the server cannot vouch for it or follow it).
