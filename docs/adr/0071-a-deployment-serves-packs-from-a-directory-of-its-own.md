# ADR-0071: A deployment serves packs from a directory of its own

- Status: Accepted
- Date: 2026-10-23
- Supersedes point 2 of [ADR-0053](0053-an-address-may-name-a-pack-served-from-a-machine.md); builds on its other points, on [ADR-0045](0045-the-indexer-is-a-package-and-check-is-a-command.md) (the working tree read by the reading rules) and on [ADR-0068](0068-a-mount-serves-the-last-indexed-commit-while-the-newest-is-not-ready.md) (what is served while a commit is indexed). The grammar is in [specs/address.md](../specs/address.md#served-from-a-machine).

## Context

An installation whose packs live where no git host can be read from, a closed network or a machine with no connection, got them so far through the `skillcdn` command alone, from a directory, one machine at a time (ADR-0053). A deployment, the server with its database, served repositories of a git host and nothing else: a `local` address was a name that is nothing to it, by decision. Such an installation wants what a deployment gives and the command does not: one server for many agents, the index in the database, the search by meaning, the search across every pack, the pages. The maintainer decided that a deployment serves directories from its own filesystem before the 0.4.0 release, under the `local` host key.

## Decision

1. **A deployment serves `local` addresses from one configured directory, and only from it.** `PACKS_DIR` names a directory whose children are owners and their children packs: `/local/<owner>/<name>` serves the directory `<owner>/<name>` under it, read as a working tree by the reading rules, as the command reads one. Nothing outside that directory is ever read, nothing in it is executed, and a deployment without the variable serves no `local` address, in the same words as any other name that is nothing.
2. **The directory is a git host of its own, behind the same port.** An adapter of the git-host port reads it: a pack is a public repository whose owner is the name of its directory, with no description and no picture; one git host answers for `gh` and the other for `local`, by the host key of the address. Everything after the port, the mount service, the indexer, the snapshots, the reader, the tools, the REST API, the pages and the search across packs, is the same code with no case of its own.
3. **The hash of the tree stands in for the commit.** A working tree has no commits, so the commit of a pack is the hash of its paths and the hashes of their bytes: the same files are the same commit, and a changed file is a new one. The directory is read again when the ref's time is up (`REF_TTL_SECONDS`) and when an administrator asks for an index now; the new commit is indexed then, and the one before answers until it is ready (ADR-0068). No ref is served: `@<ref>` is not found, as ADR-0053 says.
4. **A directory pack is verified, and its source is its page.** Whoever put the directory there vouches for it, as the person who runs the command does; no provenance notice follows. Nothing of it is at any host, so where a result would send a reader to the source, it names the page of the address at the file, at the origin `PUBLIC_URL` gives, else as a path of the deployment. The pictures a pack declares are not loaded, since the deployment serves no bytes of a file as they are; the operator gives a pack a picture as it gives any address one (ADR-0031).
5. **The operator's lists take `local` addresses.** An installation with no git host features its own packs on the explorer and vouches for or blocks them as it does any repository; a list names a name that is nothing where no directory is configured, as it may name any name.

## Consequences

- The command and the deployment serve a directory the same way: the one from the machine it runs on, the other from a directory of its own, for every agent that reaches it. An installation synchronizes its packs into the directory by any means, and they are served, indexed and searched like repositories.
- The pack and the deployment are one trust domain: the directory is read with the server's own permissions, so whoever can write to it decides what the deployment serves. A directory pack is public to everyone the deployment serves; a private directory pack is not offered.
- A pack of many files is hashed once per ref TTL per pack when asked for, not per request: the cost of a change showing up is one read of the directory, bounded by the indexer's limits.
- `GIT_HOST_KEYS` stays the git hosts and `isGitHostAddress` still narrows what needs one; what is widened is the repository coordinates of the port, which carry any host of an address, and the URL builders, which know what `local` has.
- Rejected: a second grammar or a second server for directory packs (every parser, path, URI and page already treats a `local` address as one); a `file:` URL as the source of a file (it names a path of the server's filesystem to a reader who cannot reach it, and says where the deployment keeps things); serving the bytes of a directory pack's files as they are (a route the git hosts do not need, added when a pack's pictures matter); a private directory pack (there is nobody to ask who may see it).
